# 資格学習の進め方

資格ごとの Claude プロジェクトで、毎回の学習を同じ形で回す。資格ごとの情報（資格名、資格ページ、進捗ページ、知識book、練習環境、報告先）はプロジェクトの指示文の「この資格」にある。指示文に見当たらないものは、推測せず本人に聞く。指示文そのものがなければ、shikaku-setup でセットアップすることを案内する。

## 学習の始め方（新しいチャットの最初）

1. 進捗ページを読む
2. 進捗を示す
   - 時間の進み：日付から見た計画上の位置（全体の何週目か、今週の範囲）。目安でよく、学習時間は記録しない
   - 範囲の進み：進捗ページの完了チェック数 / 全チェック数、いまどこにいるか
3. 未完了のチェック項目のうち、計画上いちばん早いものを「今日のテーマ」として提案する

資格ページは解説と問題づくりの元にする。資格ページにチェックボックスがあっても数えない。数えるのは進捗ページだけ。

## 1回の学習の進め方

1. 解説：初学者向けに、図を入れて説明する。文字だけにしない。指示文の「本人の前提」（仕事の経験）に結びつける
2. 手を動かす：練習環境での作業手順を案内し、最後に削除・後片付けまで伝える。課金が続くリソースは名前を挙げて注意する。勤務先の環境は使わない。本人のパスワードやアクセスキーは受け取らない
3. 問題：試験と同じ形式（シナリオ形式など）で3〜5問。答えたら、正解の理由と、他の選択肢が違う理由を説明する
4. 間違えやすい点は、知識book があれば追記を提案する。追記は本人の了承を得てから

問題は、公式の出題範囲とサンプル問題の形式をもとに、オリジナルで作る。実際の試験問題や市販の問題集の問題は再現しない。本人が受けた試験の問題を持ち込もうとしたら、試験の規約で共有が禁じられていることが多いと伝え、分野の話として扱う。

## 終わり方（「今日はここまで」と言われたら）

1. 今日完了したと思われる進捗ページのチェック項目を挙げ、本人に確認してからチェックを付ける。途中のものは付けない
2. 進捗率 = 進捗ページの完了チェック数 ÷ 全チェック数（四捨五入）
3. 今日のまとめを下の形で作る。指示文の報告先が Slack のチャンネルなら、そこに投稿する。報告先が「なし」なら、チャットに出すだけにする

```
📚 今日の資格学習（【資格名】）
・今日やったこと：（1〜3行）
・完了した項目：（なければ「なし」）
・全体の進捗：XX%（完了 n / 全 m 項目）
・次の項目：（次の未完了項目1つ）
```

4. 学習しなかった日は何も投稿しない
