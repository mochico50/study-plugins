# 資格学習の進め方

毎回の学習を同じ形で回す。資格ごとの情報は進捗ページにある（この学習の前提、スケジュール、弱点メモ）。見当たらないものは、推測せず本人に聞く。

## どの資格の学習かを決める

「はじめよう」と言われたら、最初にどの資格かを決める。上から順に、最初に当てはまるものを使う。

| 順 | 手がかり | 決め方 |
|---|---|---|
| 1 | プロジェクトの指示文（Claude Code なら `CLAUDE.md`）に進捗ページが書いてある | その資格で進める |
| 2 | 本人が資格名を言った（「◯◯をはじめよう」） | その資格の、本人の進捗ページを探して進める |
| 3 | どちらもない | init スキルの「設定を探す」の順で設定を見つけ、記録の置き場所から本人の進捗ページを探す |

3 で探した結果：

- 1つだけ見つかった：その資格で進める。最初に「◯◯の続きから始めます。」と一言伝える
- 複数見つかった：推測で選ばず、聞く。受験後の振り返りが済んでいるものは選択肢から外す

```markdown
勉強中の資格が2つあります。どちらを始めますか？

| # | 資格 | 進み具合 | 受験目安 |
|---|---|---|---|
| 1 | ◯◯ | 30%（12 / 40 項目） | 2026-01-20 |
| 2 | △△ | 5%（2 / 45 項目） | 2026-03-10 |

番号で教えてください。次からは「◯◯をはじめよう」と資格名を添えると、聞かずに始められます。
```

- 見つからなかった：「『◯◯の勉強を始めたい』と頼むと、スケジュールを作れます。」と案内する
- 設定に複数の人がいて、誰の進捗ページかわからない：誰の分かを聞く

決めた資格は、その会話のあいだ変えない。途中で別の資格に切り替えたいと言われたら、いまの学習を「終わり方」で締めてから切り替える。

## 伝え方

本人は shikaku の仕組みや言葉を知らない前提で話す。

- 本人に見える文は、すべて日本語で書く。ページを読んでいる途中の独り言（「もう1つページがあるので読みます」など）は書かない
- 最初に、これから何をして、何ができあがるかを1〜2行で伝える。調べものやページの読み込みをするときは、始める前に一言伝える
- 「資格ページ」「進捗ページ」「保存先」などの言葉は、その会話で初めて使うときに何のことかを添える（例：「進捗ページ（あなたのスケジュールとチェックリスト）」）
- 質問するときは、何を返せばよいかを明示する。おすすめがあれば1つに絞って示し、「OK」か、変えたいところだけで返せるようにする
- 状況の説明、おすすめの理由、質問を1つの文に混ぜない。表か箇条書きで分ける
- 終わったら、何ができたか、どこにあるか、次に何ができるかを短く伝える

## 進捗ページの読み書き

設定（または指示文）の保存先に合わせる。進捗ページが Notion の URL なら Notion、ファイルならファイルとして扱う。

| 保存先 | 読むとき | 書くとき（チェックを付けるなど） |
|---|---|---|
| Notion | 進捗ページを開く | ページを更新する |
| ファイル | 進捗ページのファイルを読む | ファイルを書き換える |
| チャット | プロジェクトのナレッジにある進捗ページを読む | 更新した進捗ページの全文を文書として出し、ナレッジのものと入れ替えてもらう（学習ノートも同じ） |

チャットの場合、書き換えは「終わり方」でまとめて1回にする。入れ替えを忘れると次回の進捗がずれるので、最後に必ず一言添える。

## 学習の始め方（新しいチャットの最初）

1. どの資格かを決め（「どの資格の学習かを決める」）、その進捗ページを読む
2. 進捗を示す
   - 時間の進み：日付から見た計画上の位置（全体の何週目か、今週の範囲）。目安でよく、学習時間は記録しない
   - 範囲の進み：進捗ページの完了チェック数 / 全チェック数、いまどこにいるか
3. 時間の進みと範囲の進みを比べる。遅れが大きければ、今日のテーマの前に「計画から遅れているとき」の手順で組み直しを提案する
4. 受験目安まで14日以内なら、「直前モード」で進めることを提案する。直前モードで進めるときは、5 と 6 の代わりにその手順に従う
5. 進捗ページの「弱点メモ」に、次の復習日が今日以前の行があれば、今日のテーマの前に復習する（「弱点メモと復習」の手順）
6. 未完了のチェック項目のうち、計画上いちばん早いものを「今日のテーマ」として提案する

資格ページは解説と問題づくりの元にする。資格ページにチェックボックスがあっても数えない。数えるのは進捗ページだけ。

## 計画から遅れているとき

遅れ = 計画上、今日までに終わっているはずのチェック数 − 完了しているチェック数。

| 状態 | やること |
|---|---|
| 遅れが1週分より少ない | 進捗を示すときに一言添えるだけ（例：「計画より2項目うしろです」）。組み直しは提案しない |
| 遅れが1週分以上、または今のペースでは受験目安までに終わらない | 下の選択肢を示して、本人に選んでもらう |
| 計画より1週分以上進んでいる | 受験を前倒しするか、余った時間を模試と弱点の補強に回すかを聞く |

選択肢は、残りの項目数と受験目安までの週数を数字で見せたうえで出す。当てはまらないものは出さない。

1. 残りの週にならし直す（週あたりの項目が少し増える。受験日は変えない）
2. 受験目安を後ろにずらす（何週ずらせば今のペースで収まるかを示す。予約済みなら変更の期限と手数料を資格ページで確認する）
3. 範囲を絞る（配点の低い分野や、本人が実務で使っている分野を軽くする。どの項目を外すかを挙げる）
4. 週の学習時間を増やす（何時間増やせば収まるかを示す）

進め方：

- 責めない。遅れの理由は聞いてよいが、聞くのは組み直しに使うため（忙しい時期がいつまで続くか、など）
- 本人が選んだら、組み直した学習プランを表で見せ、確認を得てから進捗ページを書き換える
- 完了済みのチェックは変えない。外す項目は消さず、チェックボックスをやめて「今回は見送り」の箇条書きに移す（全項目数から外れるので、進捗率の分母も変わると伝える）
- 進捗ページの「計画の変更履歴」に1行足す：日付、何を変えたか、理由
- 「今は組み直さない」と言われたら、変更履歴に「見送り」と1行残し、その週はもう提案しない

## 1回の学習の進め方

1. 解説：初学者向けに、図を入れて説明する。文字だけにしない。進捗ページの「この学習の前提」（仕事の経験）に結びつける
2. 手を動かす：練習環境での作業手順を案内し、最後に削除・後片付けまで伝える。課金が続くリソースは名前を挙げて注意する。勤務先の環境は使わない。本人のパスワードやアクセスキーは受け取らない
3. 問題：試験と同じ形式（シナリオ形式など）で3〜5問。答えたら、正解の理由と、他の選択肢が違う理由を説明する
4. 間違えやすい点は、学習ノートに残す候補として覚えておく。書き込みは「終わり方」でまとめて行う（「学習ノート」の手順）

問題は、公式の出題範囲とサンプル問題の形式をもとに、オリジナルで作る。実際の試験問題や市販の問題集の問題は再現しない。本人が受けた試験の問題を持ち込もうとしたら、試験の規約で共有が禁じられていることが多いと伝え、分野の話として扱う。

## 学習ノート

学習ノート（「ノート：名前」）は、本人だけのノート。間違えやすかったところと、本人が残したいメモをためる。場所は進捗ページと同じところ（指示文に書いてあればそこ）。見つからなければ、schedule スキルの「学習ノートを作る」の形で作る。

弱点メモとの役割の違い：

| | 置き場所 | 役割 |
|---|---|---|
| 弱点メモ | 進捗ページの表 | いつ復習するかの管理。トピック名と日付だけ |
| 学習ノート | 別のページ（ファイル） | 中身。何をどう間違えやすいか、見分け方、本人のメモ |

書くこと：

- 間違えやすいところ：問題で間違えた点や、解説で「ここは混同しやすい」と扱った点。分野の見出しの下に、トピックごとの小見出しで書く。取り違えやすいもの同士の対比は表にし、見分け方を一言で添える。必要なら図も入れる
- 自分のメモ：本人が「これをメモして」「覚えておきたい」と言ったもの。本人の言葉をなるべくそのまま残す

書き方：

- 同じトピックがすでにあれば、足さずにその項目を直す。ノートが同じ話で膨らまないようにする
- 問題文そのものは写さない。試験問題や市販の問題集の内容も書かない
- 書き込みは「終わり方」でまとめて行う。「これをメモして」と言われたものだけは、その場で書く
- 復習や解説のときは、学習ノートの該当する項目を見てから説明する。本人の過去のつまずき方に合わせるため

## 弱点メモと復習

間違えたところを進捗ページの「弱点メモ」に残し、日をあけてもう一度出す。弱点メモは表で、チェックボックスにしない（進捗率に数えないため）。

| トピック | つまずいた点 | 最後に間違えた日 | 次の復習日 | 連続正解 |
|---|---|---|---|---|
| （例）S3 のストレージクラス | 取り出し時間と最低保存期間を取り違えた | 2026-01-15 | 2026-01-17 | 0 |

記録する：

- 問題で間違えたとき、または正解でも本人が「勘で選んだ」「自信がない」と言ったときに、1行足す。同じトピックの行がすでにあれば、足さずにその行を更新する
- トピックは、資格ページの分野より一段細かい単位にする（「ストレージ」ではなく「S3 のストレージクラス」）
- つまずいた点は、何を何と取り違えたかを一言で書く。問題文そのものは写さない
- 次の復習日は、間違えた日の2日後にし、連続正解を 0 に戻す

復習する：

- 学習の最初に、復習日が来ている行から1〜3問、5分ほどで出す。前と同じ問題ではなく、同じトピックを別の場面で問う新しい問題にする
- 行が多いときは、復習日の古いものを優先して3行までにし、残りは次回に回す
- 正解したら連続正解を1増やし、次の復習日を延ばす：1回目は1週間後、2回目は2週間後
- 3回続けて正解したら「克服」とし、弱点メモの下の「克服したもの」にトピック名だけ移す
- 間違えたら、連続正解を 0 に戻し、次の復習日を2日後にする。解説は前回と違う角度（図、たとえ、対比の表）で説明し直す
- 本人が「今日は復習なしで」と言ったら飛ばす。復習日は変えず、次回また出す

弱点メモの書き込みは、問題のたびにせず「終わり方」でまとめて行う。

## 直前モード

試験の直前は、新しい範囲を広げず、模試と弱点の補強に切り替える。次のどれかで入る。

- 受験目安まで14日以内になった
- 学習プランのチェックがすべて完了した
- 本人が「直前モード」「模試をやりたい」と言った

学習プランに未完了の項目が多く残ったまま14日以内になったときは、直前モードに入る前に「計画から遅れているとき」の選択肢を先に示す。

最初に入るとき：

1. 受験日まであと何日かを示す。受験日が「目安」のままなら、予約したかを聞き、予約済みなら進捗ページの日付を直す
2. 受験前の確認を一度だけ示す：受験予約、本人確認書類、会場までの行き方（オンライン受験なら部屋・機材・回線の条件）、試験時間と問題数から見た1問あたりの時間。内容は資格ページをもとにし、資格ページの情報が古そうなら公式ページを見直す

1回の進め方：

1. 復習：弱点メモで復習日が来ているものを出す。直前モードでは3行の上限を5行に広げる
2. ミニ模試：10〜20問をまとめて出す。分野ごとの問題数は資格ページの配点に比例させ、1問あたりの時間を本番に合わせて目安の制限時間を伝える。途中で正解は言わず、全部答えてから採点する
3. 採点：全体と分野ごとの正答率を表で示す。間違えた問題と、勘で選んだ問題を解説し、弱点メモに入れる
4. 補強：正答率のいちばん低い分野に絞って、図を入れて解説し直す。手を動かす課題は、弱い分野に関係するものだけ勧める
5. 記録：進捗ページの「模試の記録」に1行足す（日付、問題数、全体の正答率、弱かった分野）。節がなければ作る。表にして、チェックボックスにしない

守ること：

- ミニ模試の正答率は、Claude が作った問題での結果であり、本番の合否の予測ではないと伝える。公式の練習問題や模擬試験があれば、そちらも受けるよう勧める
- 合格ラインを安定して超えていないまま受験日が近づいたら、延期できるか（期限と手数料）を資格ページで確認し、選択肢として示す。決めるのは本人
- 前日は新しいことをせず、弱点メモの見直しと受験前の確認だけにする

## 受験後の振り返り

「受けてきた」「合格した」「落ちた」と言われたら、まずねぎらう。それから次を聞く。一度に並べず、会話のなかで聞いてよい。答えたくないものは飛ばす。

- 結果（合否。スコアは任意）
- 実際にかかった学習時間のだいたいの合計と期間
- 役に立った教材・課題と、あまり役に立たなかったもの
- 本番で手ごたえが薄かった分野、準備が足りなかったと感じた分野
- これから受ける人に伝えたいこと

試験問題の内容は聞かず、書かない。試験の規約で共有が禁じられていることが多いため、扱うのは「どの分野が難しく感じたか」までにする。

残し方：

1. 進捗ページに「振り返り」の節を作り、上の内容を書く。受験目安の行に、受験日と結果を足す
2. 共用の資格ページへの還元を提案する。資格ページの「受けた人の振り返り」に、学習時間の実績、役に立った教材、これから受ける人への一言を足す。名前を出すか、スコアを書くかは本人に決めてもらう。書くのは了承を得てから
3. 実績が資格ページの「学習の目安」と大きく違ったら、目安そのものを直すかを聞く。1人の実績だけで数字を書き換えず、幅を広げるか注記を足す形を勧める
4. 報告先があれば、結果を報告に載せてよいかを聞いてから投稿する

不合格だったとき：

- 結果を評価しない。弱点メモと模試の記録、本人の手ごたえから、次に補強する分野を一緒に整理する
- 再受験の条件（待機期間、受験料）を資格ページで確認して伝える
- 再受験するなら、schedule の引き直しで、弱かった分野を厚くした短いスケジュールを作ることを提案する。すぐ決めなくてよいと伝える

## 終わり方（「今日はここまで」と言われたら）

1. 書き込む内容を3つまとめて挙げ、1回で確認する
   - 今日完了したと思われる進捗ページのチェック項目。途中のものは入れない
   - 弱点メモの更新（足す行、復習で変わった行、克服したもの）
   - 学習ノートに足す項目
2. 確認が取れたら、進捗ページと学習ノートに書く。本人が外したいと言ったものは書かない
3. 進捗率 = 進捗ページの完了チェック数 ÷ 全チェック数（四捨五入）
4. 今日のまとめを下の形で作る。設定（または指示文）の報告先が Slack のチャンネルなら、そこに投稿する。報告先が「なし」なら、チャットに出すだけにする

```
📚 今日の資格学習（【資格名】）
・今日やったこと：（1〜3行）
・完了した項目：（なければ「なし」）
・全体の進捗：XX%（完了 n / 全 m 項目）
・弱点メモ：新しく n 件、克服 m 件（どちらも 0 ならこの行は省く）
・次の項目：（次の未完了項目1つ）
```

5. 学習しなかった日は何も投稿しない
